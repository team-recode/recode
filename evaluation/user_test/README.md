# PHASE 13 사용자 테스트 — 진행 안내 (25절)

## 이 테스트가 재려는 것

**리포트를 받은 쪽이, 못 받은 쪽보다 "먼저 확인해야 할 곳"을 더 잘 찾는가.**

---

## 설계 — 2명 교차

|  | `jd/tenacity` | `pyeve/cerberus` |
|---|---|---|
| **사용자** | **A 조건** (리포트 없음) | **B 조건** (리포트 받음) |
| **팀원** | **B 조건** (리포트 받음) | **A 조건** (리포트 없음) |

- 두 사람 다 A·B를 한 번씩 경험한다 (25절 "순서를 바꿔가며" 반영)
- 저장소 2개는 **규모를 맞췄다** (18파일 / 함수 167 vs 195). 난이도 차이로 결과가 흔들리지 않게
- 세션 4회

### ⚠ 반드시 지킬 것

1. **A 조건을 먼저 끝내고 나서 B 조건 리포트를 연다.** 순서가 바뀌면 A 조건이 무효가 된다
2. **자기가 A 조건인 저장소의 리포트는 절대 미리 보지 않는다**
   (`reports/` 폴더에 두 파일이 다 있으니 본인 것만 열 것)
3. 두 사람이 답을 맞춰보지 않는다. 각자 적고 나중에 합친다

---

## 하는 법

### A 조건 (리포트 없이)

1. 저장소를 연다
   - tenacity: https://github.com/jd/tenacity
   - cerberus: https://github.com/pyeve/cerberus
2. **타이머를 켜고 20분** 동안 훑는다
3. "이 저장소를 내가 넘겨받았다면 **수정 전에 먼저 확인할 곳**이 어디인가"를 찾는다
4. 20분이 되면 멈추고 `응답시트.md` 의 A 조건 칸을 채운다

### B 조건 (리포트 받고)

1. `reports/B_<저장소>_HANDOFF.md` 를 연다
2. 저장소도 같이 열어 두고, **20분** 동안 리포트를 읽으며 확인한다
3. `응답시트.md` 의 B 조건 칸을 채운다

---

## 25절 질문 5개

응답시트에 들어 있다. 두 조건 모두 답한다.

1. 이 저장소에서 먼저 확인해야 할 곳을 찾았는가?
2. 어떤 질문을 원 개발자에게 하고 싶은가?
3. Re:Code가 만든 질문 중 실제로 유용한 것은 몇 개인가? *(B 조건만)*
4. 불필요하거나 과장된 finding이 있었는가? *(B 조건만)*
5. 실제 인수인계 때 사용할 의향이 있는가? (1~5점)

### 측정 항목

- 핵심 위험 지점을 찾기까지 걸린 시간
- 유용하다고 평가한 질문 수
- 사용 의향 5점 척도

---

## 이 테스트의 한계 (반드시 함께 기록한다)

25절은 **개발자 3~5명**을 요구하지만 **2명만 확보**했고, 그 2명은 **이 도구를 만든 사람**이다.

- **자기평가 편향이 있다**
- 표본이 2명 / 세션 4회다
- 25절 지시대로 **통계적 유의성을 주장하지 않는다**
- 심사 자료에는 **"팀 내부 2명 교차 테스트(세션 4회), 자기평가 편향 있음"** 으로 명시한다

숨기지 않고 밝히는 것이 21절·25절의 요구다.
